## 1. Test Case for multiple IDE Streams in one SPDM Session

The IDE streams are listed in ```streams``` of ```[Topology_x]```, for example
```link_ide:1,selective_ide:2,cxl_cm_ide:0``` or
```link_ide:1,link_ide:3:tc=1,selective_ide:2,selective_ide:4:tc=1:addr=0x80000000-0x801fffff,cxl_cm_ide:0```.
All streams are set up and torn down within one SPDM session. The streams are
set up and torn down in the order of the list. See
[ide_test_ini.md](../../ide_test_ini.md#multi-ide-section-settings) for the
rules of the list.

Stream types:
- ```link_ide```: PCIE or CXL.io Link IDE Stream, set up with IDE_KM. Its TC field is set to ```tc```.
- ```selective_ide```: PCIE or CXL.io Selective IDE Stream, set up with IDE_KM. Its TC field is set to ```tc```. The rootport Address Association Register Block is set to ```addr```, or to the device memory window if ```addr``` is not set.
- ```cxl_cm_ide```: CXL.cachemem IDE Stream, set up with CXL_IDE_KM. StreamID is always 0.

The log and the assertions name a stream by its index in the list, type,
stream_id and TC, for example ```stream[1] link_ide:3 tc=1```.

A stream is **active** if:
- ```link_ide``` / ```selective_ide```: Link/Selective IDE Stream Status Register - BIT_3:0 (Stream State) is Secure on both the rootport and the device.
- ```cxl_cm_ide```: CXL IDE Status - Rx/Tx IDE Status is Active Containment or Active Skid (matching ```cxl_ide_mode```) and CXL IDE Error Status is clear on both the rootport and the device.

A stream is **torn down** if:
- ```link_ide``` / ```selective_ide```: Stream State is Insecure on both the rootport and the device after Stream Enable is cleared.
- ```cxl_cm_ide```: Rx/Tx IDE Status is Insecure State with clear CXL IDE Error Status on the rootport, and on the device if it supports CXL_K_SET_STOP.

TestGroupSetup:
1. Requester -> SPDM session is established.
2. Requester -> QUERY / CXL_QUERY to find the PortIndex of the device.
3. Rootport has free Stream_x and key/iv slot groups for all PCIE/CXL.io streams, rootport and device have free Link IDE Stream Register Blocks for all link_ide streams and free Selective IDE Stream Register Blocks for all selective_ide streams, and the StreamIDs are not used.
4. ```addr``` of each selective_ide stream is inside the device memory window.

TestGroupTeardown:
1. Streams which are not torn down yet are torn down.
2. Requester -> SPDM session is terminated.

If a stream was torn down since the last stream setup, the next stream setup first waits 100ms, because the Root Complex IDE Programming Guide (Section 3.2) requires at least 100ms after terminating a stream before its StreamID or resources are reused.

Setup of a ```link_ide``` / ```selective_ide``` stream:
1. Requester -> KEY_PROG {StreamID, KeySet=0, RxTx in [Rx, Tx], SubStream in [PR, NPR, CPL], PortIndex}
2. KP_ACK <- Responder
3. Requester -> K_SET_GO {StreamID, KeySet=0, RxTx in [Rx, Tx], SubStream in [PR, NPR, CPL], PortIndex}
4. K_GOSTOP_ACK <- Responder
5. Set Stream Enable on the rootport and the device.

Setup of a ```cxl_cm_ide``` stream:
1. Requester -> CXL_KEY_PROG {StreamID=0, RxTx in [Rx, Tx], SubStream=1000b, PortIndex}
2. CXL_KP_ACK <- Responder
3. Requester -> CXL_K_SET_GO {StreamID=0, RxTx in [Rx, Tx], SubStream=1000b, Mode=cxl_ide_mode, PortIndex}
4. CXL_K_GOSTOP_ACK <- Responder

Teardown of a ```link_ide``` / ```selective_ide``` stream:
1. Clear Stream Enable on the device and the rootport.
2. Requester -> K_SET_STOP {StreamID, KeySet=0, RxTx in [Rx, Tx], SubStream in [PR, NPR, CPL], PortIndex}
3. K_GOSTOP_ACK <- Responder
4. Clear the keys in the rootport key/iv slots and reset the stream registers.

Teardown of a ```cxl_cm_ide``` stream:
1. Requester -> CXL_K_SET_STOP {StreamID=0, RxTx in [Rx, Tx], SubStream=1000b, PortIndex}, if the device supports it.
2. CXL_K_GOSTOP_ACK <- Responder
3. Move the rootport to Insecure State, clear LinkEncEnable, the keys and Link_Enc_Control.

### Case 1.1

Description: All IDE streams can be set up within one SPDM session, stay active during traffic and can be torn down in the order of the streams list.

TestSetup:
1. Set up all streams in list order. If a stream fails, the streams set up so far are torn down and the case is not tested.

TestTeardown:
1. Tear down all streams in list order.

Steps:
1. Check each stream.

Assertion 1.1.1 ~ 1.1.N (N is the number of streams):
    Stream is active.

2. Run traffic. Press any key to continue. A stream with ```tc``` other than 0 or with ```addr``` only sees traffic with that TC or to that range.
3. Check each stream.

Assertion 1.1.(N+1) ~ 1.1.(2N):
    Stream is active.

4. TestTeardown

Assertion 1.1.(2N+1) ~ 1.1.(3N):
    Stream is torn down.

### Case 1.2

Description: Tearing down one IDE stream does not affect the other IDE streams in the same SPDM session. At least 2 streams are required.

TestSetup:
1. Set up all streams in list order. If a stream fails, the streams set up so far are torn down and the case is not tested.

TestTeardown:
1. Tear down the streams which are left.

Steps:
1. Check each stream.

Assertion 1.2.1 ~ 1.2.N:
    Stream is active.

2. For each stream S in list order:
    1. Tear down S.

        Assertion:
            S is torn down.

    2. If S is the first stream, run traffic on the other streams. Press any key to continue.
    3. For each stream R after S in the list:

        Assertion:
            R is active.
